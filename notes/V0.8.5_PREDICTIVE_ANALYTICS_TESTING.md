## Manual Testing

### 1. Remediation Time Estimation

**Endpoint:** `GET /projects/{id}/predict/remediation-time`

**Test All Risk Levels:**
```bash
curl -s "http://localhost:8000/projects/3/predict/remediation-time" | python3 -m json.tool
```

**Expected Response:**
- Lists estimates for all 5 risk levels (Critical, High, Medium, Low, Informational)
- Each estimate includes:
  - `estimated_days`: Median remediation time
  - `confidence_interval_low/high`: 95% confidence bounds
  - `sample_size`: Number of historical findings used (0 = industry defaults)

**Test Filtered by Risk Level:**
```bash
curl -s "http://localhost:8000/projects/3/predict/remediation-time?risk_level=Critical" | python3 -m json.tool
```

**Validation:**
- ✅ `sample_size=0` means using industry defaults (no historical data yet)
- ✅ Critical: ~7 days < High: ~14 days < Medium: ~30 days < Low: ~60 days
- ✅ Confidence intervals increase with risk level uncertainty

### 2. Risk Forecasting

**Endpoint:** `GET /projects/{id}/predict/risk-forecast`

**Test:**
```bash
curl -s "http://localhost:8000/projects/3/predict/risk-forecast" | python3 -m json.tool
```

**Expected Response:**
```json
{
    "current_risk_score": 14.0,
    "forecast_30_days": {
        "date": "2025-12-08",
        "predicted_risk_score": 15.7,
        "lower_bound": 8.2,
        "upper_bound": 23.2
    },
    "trend": "stable",
    "confidence": 0.73
}
```

**Validation:**
- ✅ `trend` is one of: "improving" (negative slope), "stable" (near zero), "worsening" (positive slope)
- ✅ Confidence score 0.0-1.0 (higher = more historical data)
- ✅ Lower/upper bounds create uncertainty cone
- ✅ Dates are 30/60/90 days from current date

**Trend Interpretation:**
- **Improving**: Risk score decreasing (negative slope)
- **Stable**: Risk score flat (-0.5 to +0.5 per week)
- **Worsening**: Risk score increasing (positive slope)

**Example from Test:**
- Project 3: `trend: "stable"` (14.0 → 19.2 over 90 days = slight increase, within stable range)
- Project 4: `trend: "worsening"` (20.0 → 27.4 over 90 days = clear upward trajectory)

### 3. Anomaly Detection

**Endpoint:** `GET /projects/{id}/predict/anomalies`

**Test:**
```bash
curl -s "http://localhost:8000/projects/3/predict/anomalies" | python3 -m json.tool
```

**Expected Response:**
```json
{
    "anomaly_count": 0,
    "anomalies": []
}
```

**Anomaly Types:**
1. **Spike** - New findings discovered >2× historical average
2. **Slowdown** - Recent remediation time >1.5× historical MTTR
3. **Regression** - Previously resolved findings reopened

**How to Trigger Anomalies (for testing):**
- **Spike**: Upload a large scan with many new findings
- **Slowdown**: Let findings sit open longer than usual
- **Regression**: Set `resolved_at` to past date, then change status back to "Open"

**Example Anomaly Response:**
```json
{
    "anomaly_count": 1,
    "anomalies": [
        {
            "anomaly_type": "spike",
            "severity": "high",
            "detected_at": "2025-11-08T10:30:00Z",
            "description": "Spike in new Critical findings...",
            "affected_findings": [1, 2, 3],
            "recommendation": "Review recent infrastructure changes..."
        }
    ]
}
```

### 4. Actionable Recommendations

**Endpoint:** `GET /projects/{id}/predict/recommendations`

**Test:**
```bash
curl -s "http://localhost:8000/projects/3/predict/recommendations" | python3 -m json.tool
```

**Expected Response:**
```json
{
    "recommendation_count": 0,
    "recommendations": []
}
```

**Recommendation Categories:**
1. **Quick Wins** - Low/Medium findings with ≥5 instances (easy to fix at scale)
2. **Stale Findings** - Open >90 days (need attention or closure)
3. **SLA Alerts** - At Risk or Overdue findings (urgent action needed)
4. **Resource Allocation** - Owners with >10 open findings (overloaded)

**How to Trigger Recommendations (for testing):**
- **Quick Wins**: Create multiple instances of same Low/Medium finding
- **Stale**: Backdate `discovered_at` to >90 days ago
- **SLA**: Set findings to "At Risk" or "Overdue" SLA status
- **Resource**: Assign >10 findings to same owner

**Example Recommendation Response:**
```json
{
    "recommendation_count": 2,
```

## Interpreting Results

### Sample Size Context

**`sample_size: 0`** = Industry Defaults
- No historical data available
- Using industry-standard estimates
- Confidence intervals are wider

**`sample_size: 10+`** = Project-Specific Data
- Calculated from actual project history
- More accurate predictions
- Confidence intervals tighten

### Risk Score Weights
- Critical: 10 points
- High: 7 points  
- Medium: 4 points
- Low: 2 points
- Informational: 0 points

**Example Calculation:**
- Project with 1 Critical + 2 High = 10 + 7 + 7 = 24 risk score

### Forecast Confidence
- **0.0-0.3**: Very low confidence (insufficient data)
- **0.3-0.6**: Low confidence (some data, high variability)
- **0.6-0.8**: Moderate confidence (good data, reasonable predictions)
- **0.8-1.0**: High confidence (extensive data, stable trends)

## Troubleshooting

**Q: All `sample_size` values are 0?**  
A: No resolved findings yet. Upload scans and resolve some findings to build historical data.

**Q: `anomaly_count` always 0?**  
A: Anomalies require specific conditions. See "How to Trigger Anomalies" section.

**Q: Risk forecast shows "stable" but values increasing?**  
A: "Stable" means slope is small (-0.5 to +0.5 per week). Small increases are still considered stable.

**Q: Rate limiting not working?**  
A: Check slowapi configuration in main.py. Ensure Redis/memory storage is working.
