# v0.12.0 Unified Template System - Complete Implementation

**Date**: November 12, 2025  
**Status**: ✅ Complete and Tested  
**Type**: Major Feature - User-Uploadable Report Templates

---

## 📋 Overview

Implemented a unified template system that allows users to upload custom DOCX templates with Jinja2 placeholders. The platform fills these placeholders with actual project data during report generation. This replaces the hardcoded module system with a flexible, database-backed template architecture.

### Key Features
- ✅ Upload custom DOCX templates with Jinja2 placeholders
- ✅ Mix system and custom templates in any order
- ✅ Database-backed template storage and metadata
- ✅ Frontend UI for template management
- ✅ Backward compatibility with legacy endpoints
- ✅ Template sharing (public vs private)

---

## 🏗️ Architecture

### Database Schema
```sql
-- Extended ReportTemplate model
ALTER TABLE reporttemplate ADD COLUMN docx_file_path VARCHAR(500) NULL;

-- docx_file_path != NULL indicates user-uploaded DOCX template
-- docx_file_path == NULL indicates parameterized/widget-based template (future)
```

### Storage Structure
```
backend/storage/templates/
├── system/              # Built-in system templates (11 files)
│   ├── title_page.docx
│   ├── executive_summary.docx
│   ├── detailed_findings.docx
│   ├── top_findings.docx
│   ├── recommendations.docx
│   ├── risk_charts.docx
│   ├── sla_status.docx
│   ├── appendix.docx
│   ├── compliance_owasp.docx
│   ├── compliance_cwe.docx
│   └── jira_integration.docx
├── shared/              # User-uploaded public templates
└── projects/{id}/       # Project-specific private templates
```

### Template Flow
```
User Upload DOCX
    ↓
Store in storage/templates/
    ↓
Create database record (ReportTemplate)
    ↓
User selects template IDs
    ↓
Backend queries database → loads files
    ↓
Fill Jinja2 placeholders with project data
    ↓
Merge multiple templates into one DOCX
    ↓
Return generated report
```

## 📝 Jinja2 Placeholders Reference

### Available Variables in Templates

#### Project Variables
```jinja2
{{ project.name }}                    # Project name
{{ project.description }}             # Project description
{{ project.consultant_name }}         # Consultant assigned
{{ project.created_at }}              # Creation date
{{ project.updated_at }}              # Last update
```

#### Findings Loop
```jinja2
{% for f in findings %}
  {{ f.title }}                       # Finding title
  {{ f.risk_rating }}                 # Critical/High/Medium/Low
  {{ f.description_text }}            # HTML description (stripped)
  {{ f.remediation_text }}            # HTML remediation (stripped)
  {{ f.affected_components }}         # Comma-separated list
  {{ f.poc_text }}                    # Proof of concept
  {{ f.cvss_score }}                  # CVSS score
  {{ f.cve_ids }}                     # CVE IDs
  {{ f.cwe_ids }}                     # CWE IDs
  {{ f.owasp_category }}              # OWASP category
  {{ f.instance_count }}              # Number of instances
{% endfor %}
```

#### Risk Counts
```jinja2
{{ risk_critical }}                   # Count of Critical findings
{{ risk_high }}                       # Count of High findings
{{ risk_medium }}                     # Count of Medium findings
{{ risk_low }}                        # Count of Low findings
{{ total_findings }}                  # Total unique findings
```

#### Custom Variables (from form)
```jinja2
{{ company_name }}                    # User-provided company name
{{ report_date }}                     # Report generation date
{{ report_version }}                  # Report version
{{ consultant_email }}                # Consultant email
{{ assessment_period }}               # Assessment period
```

#### Advanced Jinja2 Features
```jinja2
{# Conditional rendering #}
{% if risk_critical > 0 %}
  ⚠️ CRITICAL: {{ risk_critical }} critical findings require immediate attention!
{% endif %}

{# Filtering findings by risk #}
{% for f in findings if f.risk_rating == "Critical" %}
  - {{ f.title }}
{% endfor %}

{# Counting with filters #}
Total High/Critical: {{ findings|selectattr("risk_rating", "in", ["High", "Critical"])|list|length }}

{# Date formatting #}
Report Date: {{ report_date|default("2025-11-12") }}
```

## 📚 Example: Creating a Custom Template

### 1. Create DOCX Template

**File: `custom_findings_summary.docx`**

```
Custom Findings Summary Report

Project: {{ project.name }}
Assessment Period: {{ assessment_period }}
Generated: {{ report_date }}

Total Findings: {{ findings|length }}
- Critical: {{ risk_critical }}
- High: {{ risk_high }}
- Medium: {{ risk_medium }}
- Low: {{ risk_low }}

Critical Findings:
{% for f in findings if f.risk_rating == "Critical" %}
  {{ loop.index }}. {{ f.title }}
     Affected: {{ f.affected_components }}
     CVSS: {{ f.cvss_score }}
     
     Description: {{ f.description_text }}
     
     Remediation: {{ f.remediation_text }}
{% endfor %}

Report prepared by: {{ consultant_email }}
```

### 2. Upload via API

```bash
curl -X POST http://localhost:8000/projects/12/templates/upload \
  -F "file=@custom_findings_summary.docx" \
  -F "name=Custom Findings Summary" \
  -F "description=Condensed findings summary for executives" \
  -F "template_type=Custom" \
  -F "is_public=false"
```

### 3. Use in Report

```bash
curl -X POST http://localhost:8000/projects/12/report/assemble/v2 \
  -H "Content-Type: application/json" \
  -d '{
    "template_ids": [5, 18, 7],
    "variables": {
      "company_name": "Acme Corp",
      "assessment_period": "Nov 1-12, 2025",
      "consultant_email": "john.doe@acme.com"
    }
  }' \
  --output report.docx
```
