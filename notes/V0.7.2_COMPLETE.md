## 📊 Import History Data Model

### ImportHistory Fields

| Field | Type | Description | Computed? |
|-------|------|-------------|-----------|
| `id` | INTEGER | Primary key | No |
| `source` | VARCHAR(50) | Import source: 'cwe', 'nvd', 'manual' | No |
| `import_type` | VARCHAR(50) | Type: 'bulk_cwe', 'single_cve', 'sync' | No |
| `file_name` | VARCHAR(255) | Uploaded file name (if applicable) | No |
| `file_size` | INTEGER | File size in bytes | No |
| `templates_created` | INTEGER | Number of templates created | No |
| `templates_updated` | INTEGER | Number of templates updated | No |
| `templates_skipped` | INTEGER | Number of templates skipped | No |
| `errors` | INTEGER | Number of errors encountered | No |
| `total_parsed` | INTEGER | Total items parsed from source | No |
| `imported_by` | INTEGER | User ID (FK to users table) | No |
| `imported_at` | TIMESTAMP | Import timestamp | No |
| `duration_seconds` | NUMERIC(10,2) | Import duration | No |
| `error_details` | TEXT | JSON error details | No |
| `success_rate` | FLOAT | Percentage of successful imports | **Yes** |

### Success Rate Calculation
```python
@computed_field
@property
def success_rate(self) -> float:
    """Calculate success rate as percentage of created+updated vs total."""
    if self.total_parsed == 0:
        return 0.0
    successful = (self.templates_created or 0) + (self.templates_updated or 0)
    return round((successful / self.total_parsed) * 100, 2)
```

**Color Coding:**
- 🟢 Green: ≥90% success (excellent)
- 🟡 Yellow: 70-89% success (warning)
- 🔴 Red: <70% success (error)

## 🔌 API Endpoints

### Import History Endpoints

#### 1. List Import History
```
GET /import-history?skip=0&limit=100&source=cwe
```

**Query Parameters:**
- `skip` (optional, default: 0): Pagination offset
- `limit` (optional, default: 100): Number of records to return
- `source` (optional): Filter by source ('cwe', 'nvd', 'manual')

**Response:** `200 OK`
```json
[
  {
    "id": 1,
    "source": "cwe",
    "import_type": "bulk_cwe",
    "file_name": "cwec_v4.14.xml",
    "file_size": 18925678,
    "templates_created": 945,
    "templates_updated": 0,
    "templates_skipped": 12,
    "errors": 3,
    "total_parsed": 960,
    "imported_by": 1,
    "imported_at": "2025-01-15T10:30:00Z",
    "duration_seconds": 45.23,
    "error_details": "[\"CWE-123: Invalid format\"]",
    "success_rate": 98.44
  }
]
```

#### 2. Get Import Details
```
GET /import-history/{id}
```

**Response:** `200 OK` (same structure as list item)  
**Error:** `404 Not Found` if ID doesn't exist

#### 3. Delete Import History
```
DELETE /import-history/{id}
```

**Response:** `200 OK`
```json
{"message": "Import history deleted successfully"}
```

**Notes:**
- Deletes only the history record
- Does NOT affect created vulnerability templates
- Useful for cleanup/maintenance

### CVE Import Endpoint

#### Import Single CVE
```
POST /vulnerability-templates/import-cve?cve_id=CVE-2024-1234&overwrite_existing=false
```

**Query Parameters:**
- `cve_id` (required): CVE identifier (e.g., "CVE-2024-1234" or "2024-1234")
- `overwrite_existing` (optional, default: false): Update if template exists

**Response:** `200 OK` (created or updated)
```json
{
  "id": 42,
  "title": "Microsoft Outlook Remote Code Execution Vulnerability",
  "cve_id": "CVE-2024-21413",
  "cvss_score": 9.8,
  "cvss_vector": "CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H",
  "risk_rating": "Critical",
  "vulnerability_type": "CWE-94",
  "description": "A remote code execution vulnerability exists...",
  "remediation": "Apply security update MS24-001...",
  "references": ["https://nvd.nist.gov/vuln/detail/CVE-2024-21413"],
  "source": "nvd"
}
```

**Error Responses:**
- `404 Not Found`: CVE not found in NVD database
  ```json
  {"detail": "CVE CVE-2024-99999 not found in NVD database"}
  ```
- `409 Conflict`: CVE already exists and overwrite=false
  ```json
  {"detail": "Vulnerability template for CVE-2024-1234 already exists"}
  ```
- `502 Bad Gateway`: NVD API unavailable
  ```json
  {"detail": "Error fetching CVE data: Rate limit exceeded"}
  ```

**Automatic Actions:**
- Creates `ImportHistory` record with:
  - source: 'nvd'
  - import_type: 'single_cve'
  - templates_created: 1 (if new) or templates_updated: 1 (if overwrite)
- Normalizes CVE ID format (adds "CVE-" prefix if missing)
- Extracts CVSS data, CWE mapping, references from NVD
- Applies risk rating calculation based on CVSS score

## 📈 Usage Guide

### Import History Workflow

1. **Perform an Import**
   - Import CWE database (POST /import-cwe-database)
   - Import single CVE (POST /import-cve)
   - History record auto-created

2. **View Import History**
   - Click "Import History" button in Vulnerability Template Manager toolbar
   - Review table with all past imports
   - Sort by date, source, success rate, etc.
   - Filter by source (CWE, NVD, Manual)

3. **Review Import Details**
   - Check success rate (color-coded)
   - View file details (name, size)
   - Review statistics (created, updated, skipped, errors)
   - Check duration and timestamp
   - Read error details if errors > 0

4. **Manage History**
   - Click refresh icon to reload data
   - Delete old records to clean up (templates unaffected)
   - Use for audit trails and troubleshooting

### CVE Import Workflow

1. **Open CVE Import Dialog**
   - Click "Import CVE" button in Vulnerability Template Manager toolbar
   - Dialog opens with input form

2. **Enter CVE ID**
   - Type CVE identifier (e.g., "CVE-2024-21413" or "2024-1234")
   - Format auto-normalized (adds "CVE-" prefix if missing)
   - Check "Overwrite existing" if updating existing template

3. **Import and Preview**
   - Click "Import CVE" button
   - Wait for NVD API fetch (2-5 seconds)
   - Review preview data:
     - CVE ID and title
     - Full description
     - CVSS score and vector
     - Risk rating (color-coded)
     - CWE mapping
     - Remediation guidance
     - Reference links (clickable)

4. **Complete Import**
   - Verify preview data is correct
   - Click "Import" button in preview
   - Success state appears with options:
     - "Import Another CVE" - stays in dialog
     - "View in Template Library" - navigates to templates

5. **Verify Import**
   - Check Import History for new record
   - Navigate to Template Library
   - Find imported CVE template
   - Verify all fields populated correctly

## 🎓 Lessons Learned

### What Worked Well
1. **Computed Fields in SQLModel**
   - `@computed_field` decorator perfect for success_rate calculation
   - Cleaner than database computed columns
   - Easy to test and modify

2. **Import History Auto-Tracking**
   - Modifying existing CWE import endpoint was seamless
   - No breaking changes to API contract
   - Backward compatible

3. **Frontend Dialog Components**
   - Material-UI DataGrid handles complex tables well
   - Color-coded chips provide instant visual feedback
   - Reusable dialog pattern established

4. **NVD Integration Reuse**
   - Existing nvd.py module required no changes
   - fetch_cve_data and parse_nvd_vulnerability worked perfectly
   - 24-hour caching prevents rate-limit issues

### Challenges Overcome
1. **Success Rate Calculation**
   - Initially considered database computed column
   - Settled on SQLModel @computed_field for flexibility
   - Ensures calculation always up-to-date

2. **CVE ID Normalization**
   - Users might enter with/without "CVE-" prefix
   - Frontend auto-adds prefix for UX
   - Backend also normalizes for robustness

3. **Error Details Storage**
   - Stored as TEXT (JSON string) for flexibility
   - error_details_parsed computed field safely parses JSON
   - Fallback to empty list if invalid JSON

### Best Practices Established
1. **Import Tracking Pattern**
   - Always create ImportHistory record for audit trail
   - Track both successes and failures
   - Store duration for performance monitoring

2. **Dialog Component Structure**
   - Three-phase workflow (Input → Preview → Success)
   - Loading states for all async operations
   - Context-aware success actions

3. **API Error Handling**
   - Specific HTTP status codes (404, 409, 502)
   - Helpful error messages with recovery suggestions
   - Frontend displays errors user-friendly
